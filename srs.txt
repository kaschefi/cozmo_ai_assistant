1. Introduction 
1.1 Purpose 
This Software Requirements Specification (SRS) defines the functional, data-driven, and non
functional requirements for the Moka AI Assistant and its systematic Tool-Routing Benchmark 
Suite. It serves as the primary engineering specification for Chapter 3 of the Bachelor's thesis, 
establishing a verifiable framework to evaluate multi-tier tool-routing architectures across scaling 
tool registries (from 20 up to 100 tools). 
1.2 Scope 
The system comprises two integrated subsystems structured to run independently of physical 
robot hardware: 
1. Desktop AI Assistant (Moka Core): A local-first, multi-modal conversational agent providing voice 
and web interaction, dual-layered PostgreSQL memory, LangGraph cognitive sub-agents (Google 
Calendar, Todoist, Python Code Execution, Weather, Web Search), workstation automation, and 
simulated robotics navigation/vision modules. 
2. Systematic Tool-Routing Benchmark & Evaluation Framework: An automated testing harness 
integrated with LangSmith evaluating three interchangeable router architectures—Variant A (Flat 
Monolithic LLM Baseline), Variant B (Hybrid Two-Stage + Top-k FAISS Tool RAG + LLM), and 
Variant C (Hybrid Two-Stage + Top-k FAISS Tool RAG + LAYA Decision Model)—measuring Top-1 
accuracy, hallucination rates, input and output tokens, and latency percentiles (P50, P90, P95) 
across scaled registries. 
2. General Description 
2.1 Product Functions 
• Multi-Modal Interaction: Captures spoken audio via Silero VAD and faster-whisper (int8 CPU) 
with conversational barge-in interruption, responding via local neural TTS (kokoro-onnx / edge
tts) and a responsive FastAPI web UI. 
• Pluggable Multi-Tier Intent Routing: Routes user requests across physical commands, workstation 
setups, system tools, or cognitive agents using interchangeable routing pipelines. 
• Dual-Layer Conversational Memory: Manages thread-level turn history and transactional states 
via LangGraph's PostgresSaver (psycopg), alongside asynchronous extraction of long-term 
biographical preferences in a vector store. 
• Simulated Autonomy & Vision Grounding: Provides hardware-free simulation modes (--dry-run 
and --source webcam) for DINOv3/REMIND visual memory, Behavior Tree execution, and 
Bidirectional A* path planning. 
• Automated Scaling Benchmark: Executes batch evaluations across labeled test queries and 
dynamically clustered synthetic tools, recording accuracy, prompt tokens, and latency. 
2.2 Operating Environment & Stack 
• LLM & Decision Models: Local qwen2.5:3b via Ollama (temperature=0.0) and 
convaiinnovations/laya-typed-decisions. 
• Embeddings & Vector Store: FastEmbed (bge-small-en-v1.5) and FAISS-CPU. 
• Persistence: PostgreSQL with psycopg and langgraph-checkpoint-postgres. 
• Evaluation Platform: LangSmith (Project WP2 / moka-router-benchmark).

4. Machine Learning & Data Requirements 
• Dataset Split: 150–300 curated queries partitioned into a Development Set (30%) for parameter 
tuning and a Holdout Test Set (70%) locked for thesis reporting. 
• Scaled Tool Registries: Expanding ~20 real tools to 30, 50, and 100 tools using thematic clusters 
with deliberate confusable pairs (cosine similarity > 0.80). 
• Core Metrics: Top-1 Routing Accuracy, Hallucination Rate (< 2%), Retrieval Recall@k, Prompt 
Token Consumption, and Routing Latency (P50, P90, P95). 
• Reproducibility: Ollama temperature locked to 0.0, deterministic random seeds, and automatic 
warmup runs prior to measurement. 
5. Non-Functional Requirements (NFRs) 
• NFR-P01 (Reflex Latency): Layer 1 FastEmbed matching must resolve within P95 < 50ms on local 
CPU. 
• NFR-P02 (Path Planning Speed): Bidirectional A* path planning must converge in < 35ms on a 
10mm grid. 
• NFR-P03 (Vision Frame Rate): Asynchronous DINOv3 extraction must maintain >= 15 FPS on 
MJPEG stream. 
• NFR-S01 (Security): Mutating endpoints must validate X-Moka-Token header against 
MOKA_ADMIN_TOKEN. 
• NFR-R01 (Graceful Degradation): System must cleanly run in dry-run mode and webcam input if 
robot hardware is absent. 
• NFR-U01 (Voice Brevity): Conversational LLM prompts must enforce spoken brevity (< 2 
sentences, zero markdown/backticks).
